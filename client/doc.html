5. Important decisions, options and trade-offs

D1. Where plans are stored (R1, R4, R5, R9)

Options: (a) server database, (b) browser localStorage, (c) IndexedDB. Chosen: (b). Works with no signal, costs nothing, needs no account system and is simple to test. Trade-offs: data stays on one device and browser, about 5 MB limit, and a cleared browser loses plans. Mitigation: JSON export/import in the library view. IndexedDB would hold more but is more code to test.

D2. How the PIN is protected (R6)

Options: (a) plain text, (b) salted SHA-256 hash, (c) server-side login. Chosen: (b) plus a 5-attempt lockout. The PIN is never stored. Trade-offs: a 6-8 digit PIN can be brute-forced by someone who copies the stored hash, and the plans themselves are not encrypted. This stops casual access, not a determined attacker. (c) is stronger but needs a server and running costs.

D3. One shared storage module (R9, R10)

Options: (a) code inside each page, (b) shared store.js. Chosen: (b). One place for rules, and it can be tested without a browser. Trade-offs: one more file to deploy, and pages break if it is missing. The earlier single-file version was easier to copy but duplicated logic and could not be unit tested.

D4. Sign-in across pages (R6, R7)

Options: (a) ask for the PIN on every page, (b) a flag in sessionStorage. Chosen: (b). One sign-in per tab; it clears when the tab closes. Trade-off: anyone using the same open tab is signed in, so the Sign out button matters on shared devices.

6. How the project meets the quality goals

GoalWhat the project doesNot covered / limits
Different users (R7)Plain-language labels; keyboard-only use; labelled fields and a linked error summary for screen readers; responsive layout for phones; works offline; tiny files for slow connections; "Inclusion prompt" field supports inclusive teaching.Only one role is built. Reviewer and Coordinator roles, and other languages, are designed but not implemented.
Protects information (R6)PIN gate, hashed PIN, lockout, data stays on the device, nothing sent over the network, the library view needs the PIN.No encryption of plans; anyone with the unlocked device and browser tools can read storage.
Lost connection and errors (R4, R8)Offline-first, so saving needs no network. The badge shows Online or Offline. Full or blocked storage shows an error instead of failing silently. Corrupted data is copied to .corrupt before reset. Unsaved edits are kept as a draft and restored after a refresh or crash.No automatic sync, so there is nothing to retry.
Affordable maintenance (R9)No server, no database, no build step, no dependencies. Free static hosting. About 600 lines in total. node --test tests/store.test.js re-checks the rules in under a second.If a server is added later, hosting and security costs begin.
